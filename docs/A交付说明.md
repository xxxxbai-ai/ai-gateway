# A 网关与整体交付说明

本版整理日期：2026-11-06。适用于用户负责的 A，以及此前按用户要求重写的浅色客户端。B/C/D 的已提交模块通过正常 Git 合并接入，分类、路由算法和模型适配实现未在本次改写。

## 直接运行

先在旧网关窗口按 Ctrl+C 关闭旧网关，然后使用这一份统一交付目录：

1. 打开 `01-启动真实网关.cmd`，在窗口填写各平台的密钥。输入不可见；回车跳过的平台本次不显示。已经设置本机环境变量时自动读取。
2. 出现 `Gateway ready: http://127.0.0.1:8080` 后保持该窗口打开，打开 `02-打开客户端.cmd`。
3. 客户端会读取模型列表。可自动选择，也可手动指定；输入问题，Enter 发送，Shift+Enter 换行。
4. 先逐个手动验证账号是否可用，再试自动模式。真实调用可能产生平台费用；模拟演示不调用外部模型。
5. 停止网关时在它的窗口按 Ctrl+C。端口被占用时启动脚本明确提示，不结束其他进程。

## 长期配置与密钥

- `网关/config/models.json`：长期配置。模型启停、五类分数、上游参数在这里；A 调用 C 的加载/保存函数。
- `网关/config/models.available.json`：启动时生成的本次可用情况，便于检查。网关不再把它作为长期配置读写位置。
- `网关/config/models.providers.example.json`：D 提供的原始示例，供参考；不会每次覆盖长期设置。
- 密钥只进入本次网关进程的环境；配置只保存 `env:变量名` 引用，不保存密钥值。
- 已有密钥的模型可以禁用、重新启用，设置立即生效并在重启后保留。原来未填写密钥的模型，启用后需要重启填写密钥才能用于真实调用。
- 本机管理接口 `GET/POST /api/config` 保留，普通聊天界面不提供改分入口。当前仍是本机服务，不宣称已经完成外网账号/权限/费用系统。

真实服务入口在启动时使用 `--require-credentials`；该选项只过滤没有凭证的真实模型，不把过滤结果保存回 C 的配置。直接运行不带此选项时沿用原有公共接口行为，缺失凭证由 D 返回结构化错误，便于独立测试。

## 日志与错误

真实入口日志为 `网关/logs/multi-requests.jsonl`。每条请求记录编号、模式、任务、最终成功模型、是否备用、耗时、错误码，以及每次尝试的模型、上游状态和可选用量。

日志不记录问题正文、回答正文和密钥。普通界面默认隐藏请求编号/规则细节，出错时可以复制诊断信息，用请求编号在日志中查找。自动只在首次明确 429/503 拒绝且未超时/取消时考虑一个不同备用模型；手动模式不换模型。

## 课堂演示：不需要真实模型额度

先关闭真实网关，再任选一个模拟入口；启动后客户端点刷新模型。

| 入口 | 操作 | 预期 |
| --- | --- | --- |
| 03-模拟正常演示 | 自动问“解释 C++ 指针” | 显示模拟回答及模拟编程模型 |
| 04-模拟备用切换 | 自动问相同问题 | 模拟编程模型返回 503，至多调用另一个备用并显示实际作答者 |
| 04-模拟备用切换 | 手动选择模拟编程模型 | 直接报错，日志只有一次尝试 |
| 05-模拟全部失败 | 自动问相同问题 | 报错，日志最多两次尝试，不会继续调用第三个 |

演示脚本只停止自己创建的模拟进程，不按端口强行结束其他程序。模拟模式始终标注，不能用固定回答证明模型能力好坏。

## 构建、测试与来源

需要 C++17、CMake、Ninja、libcurl 开发文件；客户端还需 Qt 6.5 以上。当前验证环境是 Windows 11、Qt 6.11.2、MinGW 13.1。`build-windows.ps1` 的参数可以替换其他电脑上的依赖路径，不自动下载依赖。

```powershell
.\integration\release\build-windows.ps1 -BuildPath C:\work\gateway-build
ctest --test-dir C:\work\gateway-build --output-on-failure
```

测试前为构建目录 bin 提供配套 libcurl 运行 DLL，或使用 `package.py --runtime-only`。完整构建和打包命令、实际源码版本、文件清单随交付包保存。源码压缩包带 release-info.json；没有 .git 时仍能读出交付版本。

本次新增 Windows 启动检查使用隔离目录和假凭证，实际调用 A/C 保存设置，再模拟重启，检查分数与禁用状态保持、暂缺密钥不会永久禁用模型、无密钥不会破坏配置。已有 A、B、C、D、实际模块联调和 Qt 检查也一起运行。

当前不把下列事项记成 A 的“已完成”：另一台物理电脑的人工复现、组员自己的报告/答辩准备、B 的新误判修复、真实模型能力校准、外部托管服务、双回答反馈和多轮上下文。这些分别需要组员或后续需求配合。

完整测试结果与运行包自检记录放在同级验收目录；若某项尚未实际执行，不以本说明替代通过证据。GitHub 上传与 PR 合并不由打包脚本执行。
