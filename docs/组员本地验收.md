# V1.0 组员本地验收

更新时间：2026-11-08。当前为课程交付范围内的整合验收版，等待不同电脑上的验证。各成员先验证同一版本，再讨论新功能；遇到问题请给出可复现步骤。

## 最快的运行方式：使用统一运行包

请使用组长随通知提供的完整 Windows 64 位运行压缩包，解压到一个新文件夹。不要只取一个 exe，也不要解压覆盖正在运行的旧包。运行包包含网关、新版客户端和配套依赖，通常不需要 Qt Creator、编译器或 Python。

1. 先打开 `06-检查交付包.cmd`，确认文件和配置检查通过。该检查不调用真实模型。
2. 打开 `01-启动真实网关.cmd`，在自己的电脑填写自己有权限使用的平台密钥。输入不显示；回车跳过的平台本次不显示。密钥不要发送到群里、截图或提交 Git。
3. 看到 `Gateway ready: http://127.0.0.1:8080` 后，保持网关窗口打开。
4. 打开 `02-打开客户端.cmd`，检查是否出现已填写密钥的模型。
5. 先手动指定一个模型提一个简短问题，确认账号和接口可用，再使用自动模式。

当前实际配置涵盖 DeepSeek、千问、智谱和 Kimi；没有某个平台的密钥可以跳过，不要求每人都有全部账号。不能因为模型在配置中存在就认定账号有权限调用它。

没有密钥时，可以先关闭真实网关，打开 `03-模拟正常演示.cmd`，再启动客户端、刷新模型验证模拟流程。模拟结果始终应明确标注，不能替代真实调用验收。

端口被占用时先检查旧网关是否还开着。停止网关在其窗口按 Ctrl+C；不要随意结束未知进程。

## 全组共同检查

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| T1 | 启动网关和客户端 | 无缺少 DLL 提示；模型列表正常；能连接网关 |
| T2 | 手动指定一个已配置凭证的真实模型，问“只回复：连接成功” | 得到真实回答，实际模型与指定一致 |
| T3 | 自动问“用不超过60字解释 C++ 指针” | 按配置选模，显示实际模型和回答 |
| T4 | 自动问“把我们明天下午开会翻译成英文，只给译文” | 正常返回译文；可打开详情核对分类与选模 |
| T5 | 请求代码、列表或表格回答 | 换行和代码块可读，复制内容正常 |
| T6 | 新建、切换、重命名会话，关闭后重新打开客户端 | 对话保存于本机，重启后能恢复；不同会话不串答 |
| T7 | 不输入内容尝试发送；再停止网关后刷新列表 | 空输入不发送；断线有明确提示 |
| T8 | 用 04 模拟入口，自动问“解释 C++ 指针” | 首选明确 503 后只尝试一个不同备用，显示实际作答者 |
| T9 | 同一 04 模拟入口，手动指定模拟编程模型 | 返回失败，不擅自切换模型 |
| T10 | 用 05 模拟入口，再提相同问题 | 显示失败，最多两次尝试，不无限重试 |

切换 03/04/05 前先关闭正在运行的网关，启动后客户端刷新模型。真实请求可能产生平台费用，测试使用简短问题即可。

模型可用情况和分数会影响自动选择。不同人填写的密钥不一样，模型列表和自动选择结果也可能不同，这不一定是错误。

## 更新源码

源代码在团队仓库 main。已有本地代码时，先看状态并保留自己的修改：

```powershell
git status
git switch main
git pull --ff-only origin main
```

有未提交修改时先提交到自己的工作分支或做好备份，不要直接覆盖、强制重置或强制推送。`--ff-only` 因分支分叉而停止时，把提示发给组长处理。

第一次下载源码，可克隆到一个新的目录，避免碰到旧代码：

```powershell
git clone https://github.com/xxxxbai-ai/ai-gateway.git ai-gateway-v1-check
```

拉取代码只更新源码；运行旧 exe 仍然是旧程序。当前新版客户端入口是 `client/CMakeLists.txt`，全工程入口是 `integration/release/CMakeLists.txt`，不要误用根目录保留的旧 Qt 工程。

## 需要编译时

完整构建需要 C++17、CMake、Ninja、libcurl 开发文件和 Qt 6.5 以上。可使用 `integration/release/build-windows.ps1`，通过参数传入本机 Qt、编译器、curl 头文件和库的位置；脚本默认路径来自组长电脑，不保证适用于其他成员。

Qt Creator 单独编译 `client/CMakeLists.txt` 只生成客户端，不会同时生成网关。完整工程与测试的说明见 `docs/A交付说明.md`；curl 的运行 DLL 也需要随程序提供。没有这些开发依赖时优先验证统一运行包。

## 本版边界

自动选择使用人工预设分数，不保证选到回答质量最好的模型。分类仍可能误判。历史是本机查看记录，目前不作为多轮上下文发送。停止等待不保证上游立刻停止处理或计费。

本机自备密钥、单轮、规则分类是当前范围；公众账号、计费托管、双回答投票、自动学习评分和流式聊天没有列为已完成。

本地已有 25 组工程测试和 100 条补充分类题的通过记录；这些模拟检查不能代替每个人电脑上的真实调用和界面验证。
