# 模拟演示版：现在能做什么

2026-10-26，在 Windows 11 开发电脑验证。

窗口已经接通 A/B/C/D/E 的整条模拟流程。B 实际判断题型，C 实际读取能力表选模型，
D 的 libcurl 代码实际请求本机模拟服务，窗口显示实际结果。
模拟服务回显问题来证明消息经过完整流程，不生成真实 AI 答案。

## 当前完成范围

| 操作 | 当前结果 |
| --- | --- |
| 双击窗口程序 | 自动启动随附网关和模拟服务，使用空闲端口，无需另开终端 |
| 输入编程、数学、翻译、写作或一般问题 | 显示题型、实际模型、理由、请求编号和模拟回答 |
| 顶部手动选择模型 | 使用指定模型，失败时不改用其他模型 |
| 自动模式勾选故障演示 | 首选明确拒绝后，最多尝试一个不同的备用模型 |
| 首选和备用都失败 | 最多两次调用，返回错误，不继续尝试第三个 |
| 修改启停或能力分并保存 | 新请求使用新设置；退出重开仍保留 |
| 空问题、错误字段、未知/禁用模型 | 清楚报错，不调用模型 |
| 网关停止 | 窗口提示断线；重新连接后可以继续提问 |
| 上游格式错误、超时、取消 | 保留错误，不把半截回答当作成功，不任意跨模型重试 |
| 运行记录 | 写入请求编号、题型、尝试过程、成功/失败及耗时，不保存问题原文和密钥 |

## 给组员的演示顺序

1. 自动模式输入“解释 C++ 指针”：编程题 → 模拟编程模型。
2. 输入“求解方程 x+2=5”：数学题 → 模拟数学模型。
3. 输入“把你好翻译成英文”及“写一封请假信”：类型不同，均由能力表中合适的模拟通用模型处理。
4. 手动指定模拟数学模型，再问编程题，展示手动选择有效。
5. 切回自动并打开故障开关，展示备用模型接手；再切到手动，展示失败时不换模型。
6. 关闭故障开关，将模拟数学模型的编程分改成 100 保存，重新问编程题，展示选模变化。
7. 退出后重开，展示上次设置仍保留。

设置演示会改变后续选模。需要恢复时，关闭窗口，把 `config/models.default.json` 复制为 `models.json`。
窗口中的分数是项目预设值，不代表真实测评。每次问题独立发送，不包含聊天历史。

## 本版补充的消息

原 `/api/chat` 请求及响应遵守公共接口 1.0，新增字段均可省略。

- `GET /api/models`：返回当前启用模型，并补充 `demo_mode` 布尔值供窗口决定是否开放故障开关。
- `GET /api/config`：返回所有模型的 `id/name/enabled/is_mock/scores`，不返回服务地址和凭证引用。
- `POST /api/config`：请求为 `{"models":[{"id":"mock_math","enabled":true,"scores":{"programming":100,"math":95,"translation":55,"writing":60,"general":70}}]}`。
  只更新指定模型的启停及五类能力分；保存成功返回 `{"success":true,"message":"..."}`。
  无效输入不覆盖原文件，文件通过临时文件与原子替换保存。
- `POST /api/chat` 可补充 `"demo_failure":true`，只在 `gateway --demo` 下对模拟首选生效，注入明确 HTTP 503。
  正常请求保持该字段为 `false` 或省略。手动模式不换模型；自动模式仍受至多两次调用的规则限制。
- `gateway --demo --port 0` 自动分配网关及模拟服务端口。配置中的默认本机模拟地址会在本次进程内转换为实际端口，文件原值保持不变。

真实模型模板默认禁用。未来配置账号后，需要去掉故障演示并实测真实请求，不能仅靠改开关认定通过。

## 距离最终交付还差什么

- **真实模型调用**：尚无账号，实际成功回答、真实 HTTPS 环境与自动/手动真实调用均未验证。
- **另一台电脑运行**：请组员完整解压运行包后试运行，确认演示电脑也可打开。
- **老师要求及提交材料**：按课程要求核对报告、源码、运行包和演示形式，材料只描述已验证行为。

原计划的 V0.1/V0.2/V0.3 都包含真实调用要求。现在已完成它们的多项模拟功能，
不能把包含真实调用的整版或最终 V1.0 标成完成。
