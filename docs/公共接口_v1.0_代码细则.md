制定日期：2026-10-26。由 A 按本次授权确定为模块接入基线。
接口版本 `1.0` 与项目阶段 `V0.1/V0.2/V0.3` 分别管理。
发布位置：[合并请求 #1](https://github.com/xxxxbai-ai/ai-gateway/pull/1)，分支 `codex/public-contracts-v1-20261026`。

## 1. 固定原则

- C++17，文字统一 UTF-8；模块边界只使用标准库类型，无 Qt、JSON 库或网络库依赖。
- 五类任务固定为 `programming/math/translation/writing/general`；不用中文或枚举序号跨模块传递任务。
- 模式为 `auto/manual`。自动模式 `model=nullopt`，手动模式提供非空公共模型编号。
- 公共模型编号与上游模型名称分开：`id` 对外选模，`provider_model` 供 D 调用。
- 能力分统一为按任务名称索引的 0–100 整数；人工测试分数不代表真实模型质量。
- 本版为单轮、完整回答。D 已有流式/多轮能力可保留内部实现，本版入口传 `stream=false`。

## 2. 每个模块的正式交接

所有下列名称都位于 `gateway_contract` 命名空间，完整声明见 `shared/module_api.h`。

| 负责人 | 函数 | 输入 | 输出 |
| --- | --- | --- | --- |
| B | `analyzeQuestion(message)` | UTF-8 问题字符串 | `AnalysisResult`：`task/reason/uncertain` |
| C | `loadModels(config_path)` | JSON 文件路径 | `ModelListResult`：成功标志、全部模型配置、错误 |
| C | `saveModels(config_path, models)` | 路径、全部模型配置 | `OperationResult`：成功标志、错误 |
| C | `selectModel(analysis, request, models)` | 分类、请求、同一次读取的配置快照 | `RouteResult`：首选、至多一个备用、理由、错误 |
| D | `callModel(model, request, context)` | 一个完整配置、原问题、调用上下文 | `CallResult`：实际调用结果、模型、耗时、错误等 |

B 的 `uncertain=true` 必须伴随 `task=general` 和非空回退原因。
B 允许对空白返回保守结果；A 必须先拒绝空白 HTTP 请求，不能将其继续交给路由和上游。

带 `success` 的结果必须满足：成功时 `error.code=None`、错误信息为空；
失败时错误码非 `None`、错误信息非空。资源分配等意外标准库异常由 A 捕获并转换为 `internal_error`。

## 3. 请求和模型配置

`ChatRequest` 与 HTTP 字段一致：`mode`、可空 `model`、`message`。
A 完成类型和内容校验，去掉问题首尾 ASCII 空白；其他模块保留原问题内容。

`ModelConfig` 的固定字段：

| 字段 | 含义 |
| --- | --- |
| `id/name` | 唯一公共编号、显示名称；编号不可为空、重复或为保留值 `auto` |
| `enabled/is_mock` | 是否启用、是否模拟；模拟标记不得伪装为真实 |
| `scores` | 五类任务到 0–100 整数评分的映射 |
| `provider_model` | 上游实际模型名称，不要求等于公共 `id` |
| `base_url` | API 根地址，例如 `http://127.0.0.1:18080/v1`；D 追加 `/chat/completions` |
| `credential_ref` | 空或 `env:变量名`；真实模型必须提供引用，密钥值只由 D 在运行环境读取 |
| `protocol` | 本版固定为 `chat_completions` |

示例文件为 `config/models.example.json`。JSON 顶层包含 `contract_version:"1.0"` 与 `models` 数组。
C 读取时要求字段类型正确、五项评分齐全、编号有效；配置缺失、语法或字段错误返回 `invalid_config`，不隐式替换成演示模型。
真实连接配置使用 HTTPS；本机模拟服务允许 HTTP。C 只校验字段格式，不访问网络、不读取密钥值。
配置允许全部禁用；自动选模时再返回无候选错误。

前三个公共编号沿用 `mock_code/mock_math/mock`。为复用 D 现有模拟服务，示例中的上游名称分别为
`demo-code/demo-general/demo-language`；这只是配置映射，不要求 D 重命名现有模拟服务。
`real_a` 为默认禁用的真实模型模板，验证实际服务后再填写并启用，其评分也是演示预设值。

## 4. C 的选择与配置生效规则

- 自动模式：过滤禁用及当前任务不合格的配置，按当前任务分数降序，同分按公共 `id` 字典序升序。
  第一名为 `primary_model`，第二名为可选 `fallback_model`；没有第二名则为 `nullopt`。
- 手动模式：验证指定编号存在、启用且调用参数有效；首选固定为它，备用必须为空，能力分不改变指定结果。
- 首选与备用必须来自输入配置，编号不同。失败时首选为空、备用为空，错误信息非空。
- 请求模式或字段不合法为 `invalid_request`；未知模型为 `unknown_model`，禁用模型为 `disabled_model`；
  无合格候选为 `no_available_model`；重复编号等整体配置冲突为 `invalid_config`。
- A 在每次聊天和模型列表请求时读取配置。同一次聊天的分类、选模、调用使用同一份快照。
- C 保存时验证配置，并确保失败不破坏原文件；保存成功后新请求按新文件读取，重启仍然生效。

前三个模拟模型的预期首选：编程 `mock_code`、数学 `mock_math`、翻译/写作/通用 `mock`。
V0.1 已有的两参数选模函数可保留；按新签名增加包装或扩展实现，逐步补上手动、备用和配置读写。

## 5. D 的结果与 A 的备用策略

D 每次只调用传入模型一次，不选模、不在内部跨模型重试。
`CallResult.model_id` 是传入的公共编号，失败也填写；`request_id` 沿用 A 创建的编号。
只有完整回答成功才返回 `success=true`。失败时可以保留诊断数据，A/E 不得将不完整内容展示为成功回答。
`elapsed_ms` 用单调时钟记录本次尝试耗时；`http_status` 为实际上游状态，没有响应时为 0。

`RequestContext` 延续 D 已有实现的预算：连接 5 秒、首次响应 30 秒、整个请求总计 120 秒。
A 创建一次上下文，首选与备用共用同一总截止时刻和取消标志；切换不得重置总预算。
E 的整体等待预算设为 130 秒。此处取代旧计划中 10/25 秒的建议值。

A 仅在以下条件全部满足时调用 C 已返回的备用：

1. 自动模式，第一轮失败，尚未向用户输出回答，也未取消、未到总截止时刻。
2. D 报告 `UpstreamRejected`、`explicit_rejection=true`，且上游状态是 429 或 503。
3. 备用存在、有效、启用且与首选不同。

公共辅助函数 `mayUseFallback` 检查前两项及调用次数；A 仍负责核对备用候选，并限制总调用最多两次。
手动模式、鉴权错误、连接失败、超时、无效响应和取消均不触发备用。这与 D 当前的保守实现一致。
备用再次失败直接返回错误，不再选择第三个模型。

## 6. A/E 的 HTTP 契约

沿用本机 `http://127.0.0.1:8080` 和三个接口，不将 D 的上游路径作为客户端路径。

| 请求 | 行为 |
| --- | --- |
| `GET /health` | `{"success":true,"status":"ok"}` |
| `GET /api/models` | `success/models`；仅返回启用且配置有效项的 `id/name/is_mock`，不向客户端暴露连接或凭证字段；不承诺上游实时可达 |
| `POST /api/chat` | 接受 `mode/model/message`，JSON、UTF-8；自动模式 `model:null`，手动模式为公共编号 |

输入错误返回 400，不调用模型。请求三个字段必须存在、类型正确；问题去首尾 ASCII 空白后非空。
新增未识别字段可忽略，保留现有客户端的兼容性。

集成版成功响应：

```json
{
  "request_id": "example-001",
  "success": true,
  "task": "programming",
  "uncertain": false,
  "selected_model": "mock_code",
  "is_mock": true,
  "reason": "分类理由；选模理由；如有切换，再附切换说明",
  "answer": "模型返回的完整回答",
  "fallback_used": false
}
```

`selected_model/is_mock` 必须对应最终成功作答模型；`fallback_used` 表示实际发生过备用调用。
旧版模拟网关在接入 B/C/D 前仍可返回 `task:null` 并省略新增字段，须标注为旧模拟流程；V0.2 集成验收要求实际任务名称。
现有 Qt 可以忽略新增字段，E 后续按迁移清单增加展示。

失败保持原有可读 `error`，新增稳定的 `error_code`：

```json
{"request_id":"example-002","success":false,"error_code":"unknown_model","error":"指定的模型不存在"}
```

| 错误组 | HTTP 状态 |
| --- | --- |
| 输入错误、未知或禁用模型 | 400 |
| 主动取消 | 408 |
| 配置错误、内部异常 | 500 |
| 无效或不完整上游响应 | 502 |
| 无候选、网关缺少上游凭证、连接或上游调用失败 | 503 |
| 连接、首次响应、总预算超时 | 504 |

机器错误名与映射以 `ErrorCode/errorCodeName/httpStatus` 为准。上游 401 不直接作为客户端登录错误；
本组客户端没有上游账号，A 将其作为上游拒绝返回 503，并展示去除敏感信息后的说明。

## 7. 旧代码如何接入

| 成员 | 本轮需要修改的内容 |
| --- | --- |
| A | 维护 `shared/`；在 `handle_chat` 调用公共函数；处理结果、错误码、日志与最多两次调用；每次请求读配置 |
| B | 已采用公共 `AnalysisResult/analyzeQuestion`；保留 `classification` 旧入口别名，继续维护规则和样例 |
| C | 为现有 `routing` 模块增加公共签名；保留规则，实现模式、备用及配置读写；不再另定义跨模块配置格式 |
| D | 给现有 `ProviderAdapter` 增加 `callModel` 包装；公共配置映射到已有调用配置，保留网络实现；提供可复现依赖和真实调用记录 |
| E | 保留 HTTP 路径与请求字段；动态加载模型列表，显示任务、理由、实际模型、真实/模拟及切换状态，处理等待和错误 |

D 的最小转换：`message→question`、`is_mock→simulated`，其余连接字段同名复制。
上下文复制同一 `request_id/deadline/timeout/cancelled`；`AttemptResult.ok()` 映射成功标志，
其 `model_id/answer/http_status/elapsed_ms/explicit_rejection` 映射到公共结果。
旧 `ProviderErrorCode` 按名称映射；`CallbackFailed` 映射为本版 `InternalError`。
D 的调用适配不需要旧能力数组，路由统一由 C 使用 `scores`，避免将 0–100 评分压成旧 0–5 数组。
其他旧枚举若仍需使用，按名称映射，不能按序号强转。
