## 一、先统一这次课的验收目标

**本次课结束时：Qt 客户端能向现有网关发送“你好”并显示模拟回答；B、C、D 各有一个能单独运行的小模块；真实模型调用已开始验证。**

这次课先验证收发连接和各模块的基本功能。分类、路由、模型调用全部串起来，是下一版的目标。

### 1. 当堂要实际演示的结果

| 编号 | 验收动作 | 应看到的结果 | 主责 |
| --- | --- | --- | --- |

## 二、当前起点与最终完成标准

### 1. 当前已知起点

- 已有小组开发约定和客户端/网关接口草案。
- 当前本地 C++ 网关实现了 `/health`、`/api/models`、`/api/chat`，可以返回模拟回答。
- 本地网关已通过 14 个自动测试方法；这不代表 Qt 联调或真实模型调用已经完成。
- 当前已有 `GatewayClient/` Qt 窗口雏形，可以读取输入并显示文字；尚未接入网关 HTTP 请求，B/C/D 独立业务模块和真实模型适配也尚未完成。
- 远程仓库及各成员电脑上的最新状态，应在 D1 由本人补报。

### 2. D14 最终必须做到

1. Qt 客户端可以输入问题、选择自动或手动模式、读取模型列表，显示回答、实际模型、选择理由和错误。
2. 网关进行输入校验，通过明确接口调用分类、路由和模型接入模块，并返回约定的 JSON。
3. 规则识别 `programming`、`math`、`translation`、`writing`、`general` 五类问题；无法明确判断时说明原因并归入通用问答。
4. 至少三个可区分的模型配置项，支持能力评分、启停状态、自动选模和手动指定。其中至少一个接入真实大模型，其余可以是明确标注的模拟模型。
5. 至少演示一次：Qt 提问 → 网关分类 → 自动选择真实模型 → 真实调用 → Qt 显示真实回答。手动指定真实模型也必须可用。
6. 自动模式首选调用明确失败后，最多再调用一个不同的合格备用模型；手动模式失败时返回错误。
7. 有可修改并保存的模型配置、基础日志、可重复测试、运行说明和演示材料。
8. 模拟与真实结果清楚区分。模拟流程用于验证路由及故障行为，不能替代真实模型接入验收。

最终目标按现有小组约定和本次补充的“必须真实调用”要求安排。老师的其他原始评分要求，需要 A 在 D1 核对；若有变化，当天调整本计划。

至少一次自动模式问题，实际走过 B 分类、C 选模、D 真实调用，并在 Qt 显示真实结果。不能一直只展示“手动真实、自动模拟”。

### D9 前必须验证的场景

| 场景 | 预期结果 | 验证方式及责任 |
| --- | --- | --- |
| 自动选择真实模型 | 分类及评分符合配置，真实模型作答 | A/C/D/E 联合，保留请求编号和调用记录 |
| 手动指定真实模型 | 实际使用指定模型 | A/C/D/E 联合 |
| 自动首选模拟模型明确失败 | 最多切换到一个不同的合格备用模型；成功时 `selected_model` 是最终作答模型，`fallback_used` 为 `true` | D 提供确定失败方式，C 提供候选，A 编排，E 显示 |
| 手动指定会失败的模型 | 返回错误，只调用一次 | A/D 检查调用记录，E 检查提示 |
| 首选与备用都失败 | 返回错误，调用总次数不超过两次 | A/C/D 联合 |
| 无启用模型或无合格候选 | 返回清楚错误，不调用上游 | C 给出错误，A 处理，D 确认未调用 |
| 修改启停或能力评分并保存 | 新请求按照新配置选模；重启后保存仍有效 | C/A 验证，E 重新加载模型列表 |
| 空问题、错误字段、未知模型 | 返回输入错误，不调用模型 | A 维护接口测试，D 核对调用记录 |
| 上游超时或网络失败 | 有清楚错误，客户端恢复可操作状态；自动模式仍遵守至多一次备用限制 | A/D/E 联合 |

本阶段允许用独立的模拟配置精确复现失败与排序，再用包含真实模型的配置验证真实流程。两种配置要在演示时明确说明。

| D | 整理真实模型运行所需条件、依赖、错误处理与耗时记录；准备真实调用与模拟故障演示 | 适配说明、真实调用证据、故障演示步骤及报告部分 | 演示电脑真实调用可用；不把密钥打包进仓库或材料 |
| E | 完善必要界面提示；检查窗口尺寸、中文显示和长回答；整理 Qt 运行依赖并录制界面演示 | 客户端运行包、界面说明、演示截图或视频 | 演示电脑及备用电脑均可启动，主流程与异常提示可复现 |

### 冻结与交付

- D10–D12：修复、跨电脑复现、整理材料和至少一次完整彩排。只在全部核心场景通过、资源已就绪时考虑接入第二个真实模型。
- D12 结束：固定交付版本；功能清单和报告内容以实际实现为准。
- D13：处理会阻止启动、真实调用或演示的缺陷，复验相关场景；再完整彩排一次。
- D14：核对老师要求，提交源码、运行包及文档；保留提交成功记录。

报告、截图、测试、演示由每个人整理自己模块的内容，A 负责汇总和一致性检查。

## 八、先确认这些公共约定，快慢成员才能独立推进

### 1. 输入输出建议

下面是 D1 要共同确认的接口建议，不表示当前已经有这些实现。确认后在公共头文件中写下准确 C++ 类型、函数签名和空值约定。

| 模块 | 函数名称建议 | 输入 | 输出至少包含 |
| --- | --- | --- | --- |
| B | `analyzeQuestion` | 问题字符串 | `task`、`reason`、`uncertain` |
| C | `loadModels` | 配置文件路径 | 模型配置列表；读取失败的错误 |
| C | `selectModel` | 任务类型、模式、指定模型编号、模型配置列表 | 是否成功、首选编号、备用编号、理由、失败原因 |
| D | `callModel` | 完整模型配置、问题字符串 | 是否成功、回答、实际模型编号、耗时、错误类别及说明 |

模型编号由 C 统一定义。D 根据同一份配置调用，A 根据编号取得配置并协调各模块，E 从模型列表获取可选择的编号。

模型配置先约定：`id`、显示名称、`enabled`、`is_mock`、五类能力评分，以及 D 调用真实模型所需的服务地址、上游模型名称、密钥环境变量名称、超时等字段。密钥本身在本机环境中配置。

公共结果优先使用 C++17 标准类型，业务模块无需依赖 Qt 窗口。网关与客户端通过 HTTP 通信，可以分别构建、分别运行。

### 2. 一份可直接用于模拟测试的能力表

评分范围建议统一为 0–100。以下是测试用的人工预设评分，用来检验程序是否按规则选择，不用于证明真实回答质量。

| 模型编号 | 是否模拟 | 编程 | 数学 | 翻译 | 写作 | 通用 |
| --- | --- | --- | --- | --- | --- | --- |
| `mock_code` | 是 | 95 | 70 | 55 | 60 | 70 |
| `mock_math` | 是 | 60 | 95 | 55 | 60 | 70 |
| `mock` | 是 | 65 | 65 | 90 | 90 | 90 |

预期：编程选 `mock_code`，数学选 `mock_math`，翻译/写作/通用选 `mock`。不同任务可以选到同一个模型。

同分按事先确定的固定顺序排序，例如模型编号字典序。无备用模型时可以保留首选，不能为凑备用重复选择同一模型。

合格候选指：配置有效、处于启用状态、有当前任务的评分且调用参数齐全。自动模式按评分从高到低选首选和下一名备用；手动模式校验指定模型后直接使用它。

V0.3 的配置生效方式建议统一为：A 在每次聊天请求和模型列表请求时调用 C 的配置读取函数；同一次聊天的选模和调用使用同一份读取结果。C 将修改保存到该文件，下一次请求即可看到变化；保存后重启仍保留。配置读取失败要报明错误，先不引入缓存或额外的配置编辑界面。

真实模型接通后，加入单独的演示配置，记录真实模型编号与 `is_mock: false`，并保证至少有一个自动模式场景实际选择它。

### 3. 分类测试建议

V0.1 先五类各一条；V0.2 冻结 30 条：五类各五条明确问题，共 25 条，再加五条混合或模糊问题。每条都预先写清类型与理由，再运行代码记录实际结果。

例如“翻译这段 C++ 报错”主要要求翻译，不能仅因为出现 C++ 就认定为编程；真正无法区分时，按约定返回通用问答并解释。

明确单一意图的基本样例应全部符合规则；混合和模糊样例按约定优先级或保守回退验证。结果只说明这份测试集上的表现，不代表所有问题都能正确分类。

### 4. 外部 HTTP 与错误规则

- 保留现有三个接口及请求字段，继续使用 UTF-8 JSON；`/api/chat` 成功时返回 HTTP 200，输入错误返回 400。
- `selected_model` 表示最终成功作答模型；`reason` 包含分类、选模及必要时的切换说明；真实/模拟身份与模型列表一致。
- 手动未知或禁用模型返回输入错误；无可用模型或上游明确失败，建议返回 503；最终因超时失败建议返回 504。A/D/E 在接入这些场景前共同确认并更新接口约定。
- D 单次 `callModel` 只负责一个模型。跨模型切换由 A 编排，避免 A 和 D 各重试一次而超出上限。
- A/D/E 确认超时预算：客户端等待时间要覆盖自动模式最多两次调用及处理余量。可先约定单模型 10 秒、客户端 25 秒，再按实际调用条件调整并统一记录。
- 各成员不能单独改公共字段、类型名称或函数签名；需要改时，说明受影响模块并一起更新。

## 九、做得快的怎么继续，做得慢的怎么补齐

### 1. 先完成者按自己的模块继续下一版

| 成员 | 可以怎样独立开发下一版 | 需要别人提供的最小信息 |
| --- | --- | --- |
| A | 用返回固定约定结果的临时函数演练模块串接、错误响应和日志，再替换为成员的实际代码 | 冻结后的函数签名和结果结构 |
| B | 增加规则、混合题及样例，完善测试 | 五类名称和输出结构 |
| C | 用固定任务字符串和示例配置开发路由、备用、配置保存 | 模型配置字段和任务名称 |
| D | 独立实现模拟成功/失败、真实调用及超时 | 模型配置字段、真实接口资源 |
| E | 连现有网关做收发，用事先约定的样例响应预览分类、错误及切换显示 | HTTP 约定及响应样例 |

临时函数和样例响应要明确标注。它们可以支持开发，但不能替代实际模块接入验收。

### 2. 版本通过要区分个人与整体

- 个人模块通过某版验收后，可在自己的工作分支继续下一版。
- 共享的可运行版本只合入能构建、接口兼容的代码；开发中的未完成代码保留在个人分支。
- 全组版本只有在该版的整体检查项通过后，才能标记为通过。每版记录对应提交位置，保留前一版可运行状态。
- 每个人只修改自己模块；公共头文件、总构建和对外接口的修改由 A 协调，受影响成员共同检查。
- 合入时，每人负责修复自己的模块与构建问题，A 负责定位连接处并安排顺序。

### 3. 落后时交付“最小补齐项”

例如 B 暂时写不完整规则，就先完成五条明确样例和保守回退；E 暂时没有模型选择框，就先跑通自动模式的真实 HTTP 收发。先保证该版最低要求，再继续完善。

每天课后或约定时间，每人更新一次四行信息：

```text
已完成：具体功能与代码位置
已验证：输入、实际输出、运行方式
当前卡点：哪一步、报错或缺少什么
下一步：要交什么、预计何时可检查
```

卡住约 30 分钟仍无进展，就带上代码入口、尝试步骤、报错及期望结果找相关同学协助。连续一天影响关键流程时，A 拆小任务或安排两人共同排查，原负责人继续完成修复。

### 4. 两个优先处理的关键依赖

- 真实模型资源：D1 开始，D2 前必须实际取得回答。若失败，当天区分账号/额度、密钥、网络、模型名称、请求格式或 HTTPS 依赖问题，由 A/D 明确处理负责人和替代的可用真实接口。不能一直等到最后一周，也不能把模拟结果标成最终完成。
- Qt 可运行环境：D1 先启动最小窗口，再做界面。遇到套件或编译问题先解决，网关继续独立推进；客户端和网关分进程运行，无需为了收发 HTTP 强行使用同一个编译器。
