当前统一基线见 [公共接口 1.0](公共接口_v1.0.md)，包含内部签名、配置、错误码和 HTTP 扩展字段。

## 1. 本阶段要做到什么

用户在客户端输入问题，客户端发送给网关，网关返回固定模拟回答，客户端显示回答。

本阶段使用编号为 `mock` 的模拟模型。接入 B 的分类、C 的路由和 D 的模型调用后，沿用下面的字段，填入实际处理结果。

## 2. 共同约定

- 网关默认地址：`http://127.0.0.1:8080`。客户端和网关运行在同一台电脑上。
- 请求与响应使用 JSON 格式，文字使用 UTF-8 编码。
- 聊天请求设置 `Content-Type: application/json`。
- 成功时返回 HTTP 状态码 200；本阶段输入有误时返回 400，并附上可读错误信息。
- 修改字段名称或含义前，先通知相关组员并更新本文档。

## 3. 接口一览

| 请求方式 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 检查网关是否运行 |
| GET | `/api/models` | 获取模型列表 |
| POST | `/api/chat` | 提交问题并获取回答 |

## 4. 检查网关：GET /health

客户端请求 `http://127.0.0.1:8080/health`，无需提交字段。

正常运行时返回：

```json
{
  "success": true,
  "status": "ok"
}
```

`success` 表示请求成功；`status` 为 `ok` 表示网关正在运行。

## 5. 获取模型列表：GET /api/models

客户端请求 `http://127.0.0.1:8080/api/models`，无需提交字段。

第一次联调时返回：

```json
{
  "success": true,
  "models": [
    {
      "id": "mock",
      "name": "模拟模型",
      "is_mock": true
    }
  ]
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| success | 布尔值 | 是否成功 |
| models | 数组 | 当前可供选择的模型列表 |
| 每个模型的 id | 字符串 | 程序使用的模型编号；手动选模时发送此值 |
| 每个模型的 name | 字符串 | 客户端显示给用户的名称 |
| 每个模型的 is_mock | 布尔值 | 是否为模拟模型，便于客户端明确标注 |

## 6. 提交问题：POST /api/chat

### 6.1 客户端发送什么

自动模式示例：

```json
{
  "mode": "auto",
  "model": null,
  "message": "你好"
}
```

手动模式示例：

```json
{
  "mode": "manual",
  "model": "mock",
  "message": "你好"
}
```

| 字段 | 类型 | 是否必填 | 含义与规则 |
| --- | --- | --- | --- |
| mode | 字符串 | 是 | `auto` 表示自动选模；`manual` 表示手动选模 |
| model | 字符串或 null | 是 | 自动模式填 `null`；手动模式填模型列表中的 `id` |
| message | 字符串 | 是 | 用户的问题；去掉首尾空白后不能为空 |

第一次联调时，自动模式选择 `mock`；手动模式可以指定 `mock`。

### 6.2 成功时返回什么

```json
{
  "request_id": "demo-001",
  "success": true,
  "task": null,
  "selected_model": "mock",
  "reason": "当前使用固定模拟回答验证连接",
  "answer": "模拟回答：你好",
  "fallback_used": false
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| request_id | 字符串 | 网关为每次请求生成的唯一编号；示例编号仅用于说明 |
| success | 布尔值 | `true` 表示成功 |
| task | 字符串或 null | 问题类型；第一次联调先填 `null`，接入分类模块后填实际类型 |
| selected_model | 字符串 | 实际作答模型的编号；发生备用切换时填最终成功模型的编号 |
| reason | 字符串 | 选模及必要时切换备用模型的简短理由；本阶段注明固定模拟回答 |
| answer | 字符串 | 显示给用户的回答 |
| fallback_used | 布尔值 | 是否实际切换过备用模型；第一次联调填 `false` |

接入分类模块后，问题类型统一使用：`programming`（编程）、`math`（数学）、`translation`（翻译）、`writing`（写作）、`general`（通用问答）。

### 6.3 输入有误时返回什么

空问题示例：

```json
{
  "request_id": "demo-002",
  "success": false,
  "error": "问题不能为空"
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| request_id | 字符串 | 本次请求编号 |
| success | 布尔值 | `false` 表示失败 |
| error | 字符串 | 客户端可以直接显示的错误说明 |

本阶段检查：JSON 格式有误、缺少字段、字段类型有误、模式不合法、自动模式 model 非 null、空问题、手动模式未指定模型或指定了不存在的模型。出现这些情况时返回错误。

## 7. 第一次联调验收

- 请求 `/health`，能看到网关正常运行的结果。
- 客户端读取 `/api/models`，能显示“模拟模型”。

- 手动指定 `mock`，能取得同样的模拟回答。
- 提交空问题，能显示“问题不能为空”。

以上为计划验收项，实际执行后再记录是否通过。
