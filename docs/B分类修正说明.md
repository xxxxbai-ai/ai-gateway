# B 分类修正说明

日期：2026-11-06。由组长明确授权直接修正 B 模块，保留 B 原有实现、公共入口和测试，再增加规则与回归题。没有更改 C 的模型能力分数，也没有更改 D 的厂商调用代码。

## 这次具体修了什么

以前主要依赖“看到某个词就加分”。现在先排除明确否定和输出语言要求，识别用户要执行的动作，再结合上下文判断。

| 问题 | 原表现 | 修正后的分类 |
| --- | --- | --- |
| 我的对象生气了，怎么哄？ | 编程 | 日常问答 |
| 我的信用卡积分怎么兑换礼品？ | 数学 | 日常问答 |
| Python 是什么动物？ | 编程 | 日常问答 |
| 父母的遗产继承需要准备哪些材料？ | 编程 | 日常问答 |
| 解释数学中函数的定义 | 编程 | 数学 |
| 用英文解释 C++ 的继承 | 混淆为不确定任务 | 编程；英文只是回答语言 |
| 翻译软件和词典有什么区别？ | 翻译 | 日常问答；讨论工具区别 |
| 不要写代码，直接求解方程 x+3=5 | 编程 | 数学；排除被否定的编程要求 |
| 帮我把这句话说得更礼貌一点 | 没有识别到专门任务 | 写作 |
| 已知三角形两边长 3 和 4，夹角 90 度，求第三边 | 没有识别到专门任务 | 数学 |

同时补充网页提交白屏、英文几何表达等线索。保留“翻译这段 C++ 报错”归翻译、“写个函数计算平方根”归编程的规则。

只有“函数／对象／积分／继承”几个孤立多义词时，不强行指定专门类别，返回通用问答并标记不确定。同时要求翻译和润色且主任务不清楚时，也保守回退。

“把代码改得更简洁”继续归编程；“把一句话改得更礼貌”归写作。不是把所有“改得更……”都当成写作。

## 没有变化的公共约定

入口仍为 `gateway_contract::analyzeQuestion(const std::string&)`，仍返回 `task/reason/uncertain`，五个任务名保持原样。A/C/D 不需要改调用方式。

所有处理都发生在 B 的分析副本上，用户原问题不会被删除、改写或截断。超过 8192 个 UTF-8 字节的内容直接保守返回 `general/uncertain=true`，由后续模型接收原文。这个限制针对规则分析工作量，不是聊天输入框的字符限制。

B 的“规则得分”是判断任务的人工证据权重；C 的“模型得分”是选择模型的预设能力分。两者用途不同。本次只改前者的规则，没有测量或调整模型能力排名。

## 如何验证

- 原有 46 条接口/边界题、21 条 CLI 回归题、五类演示及 128 次并发调用继续运行。
- `v03_frozen_30.tsv` 的原文、预期标签与判断条件保持不变。
- `v1_semantic_30.tsv` 来自之前已经记录的 30 条补查问题，保留原建议标签；原报告中只有 13 条匹配，本次修正其余 17 条。
- `v1_variants.tsv` 增加 70 条补充与改写题，包含相近用词的不同任务、英文表达、局部否定、明确与模糊上下文，也检查 `return 42;` 等短代码片段和普通英文 `return/class` 的区别。
- 每条 TSV 题检查任务、预期不确定标志、理由非空（或指定依据）、连续四次调用一致，以及“不确定时只能返回 general”的公共约定。
- 超长输入、长度边界和原输入不被修改另有接口检查。

这些是回归测试，不是随机抽样的准确率评估，也不是模型训练。不能把题集全部通过宣传成真实问题分类准确率 100%。旧报告的 13/30 是那组特意补查问题的结果，同样不能当作整体准确率。

统一构建后运行 CTest，报告中的 `analyzer_frozen_30`、`analyzer_semantic_30`、`analyzer_variants` 可分别检查三组题。构建目录 `shared/analyzer/` 会生成逐题实际结果 TSV，便于 B 对照阅读。

## 给 B 的代码范围

主要修改 `modules/analyzer/question_analyzer.cpp`，配套修改本目录的 `tests.cpp`、`evaluation.cpp`、`CMakeLists.txt`、`README.md`，增加两份题集。没有改公共头文件，也不需要 B 修改 C/D 的代码。

交付目录另外提供“B分类修正.patch”，只包含 B 模块与本说明，供 B 与自己的代码对照；整合版源码和运行包已经包含修正。不要对已经包含这些改动的目录再次应用补丁。

## 仍然存在的边界

当前是规则分类，不能像语言模型一样理解任意自然语言。反讽、复杂嵌套引述、多层否定、一个问题中多个任务的先后关系、未收录的多义词等，仍可能误判。新发现的问题应增加对照题，并保留旧题重新检查。手动选择模型仍可使用。

本次不增加收费的模型分类调用，不改变自动选模的预设评分方式，不实现双回答投票或自动学习评分。这些应作为另外的明确需求评估。
